Introducción y Arquitectura del Sistema

Este documento constituye el Libro de Fundamentos Técnicos del Sistema de Análisis Monte Carlo para el Taller de Rango de Costos de CODELCO. Proporciona transparencia matemática completa (Caja Blanca) que permite a auditores del proyecto validar los resultados del sistema caso por caso, siguiendo los estándares AACE International y PMI.

La arquitectura de tres capas del sistema garantiza trazabilidad completa:

  • Interfaz web con formulario de ingreso y validación de datos
  • API REST de cálculo que ejecuta el motor Monte Carlo con N iteraciones
  • Base de datos relacional que persiste inputs, resultados y metadatos de auditoría por usuario

Distribuciones de Probabilidad

2.1 Distribución Triangular T(a, c, b)

La distribución triangular T(a, c, b) se define por tres parámetros: a = mínimo, c = moda (más probable), b = máximo. Es la distribución de referencia para modelar incertidumbre de ítems de costo cuando no se dispone de datos históricos suficientes. La requieren los estándares AACE para CRA y SRA.

Función de Densidad de Probabilidad (PDF)

f(x) = 2(x − a) / [(b − a)(c − a)]     para a ≤ x ≤ c
f(x) = 2(b − x) / [(b − a)(b − c)]     para c < x ≤ b

Estadísticos Analíticos

EstadísticoFórmula
Media (valor esperado)E[X] = (a + c + b) / 3
VarianzaVar[X] = (a² + c² + b² − ac − ab − cb) / 18
ModaMo = c (parámetro de entrada directo)

2.2 Muestreo por Inversión de CDF — Método Exacto O(1)

El sistema genera muestras usando el método de inversión de la CDF. Dada u ~ U(0,1), la muestra se obtiene en O(1) sin iteraciones ni rechazo:

Sea u ~ U(0,1) — número pseudo-aleatorio uniforme
Umbral de la moda: F_c = (c − a) / (b − a)

Si u < F_c :    x = a + √[ u · (b−a) · (c−a) ]
Si u ≥ F_c :    x = b − √[ (1−u) · (b−a) · (b−c) ]
⚡

Propiedad Clave

Complejidad O(1) por muestra — sin rechazo, sin iteraciones. Es el mismo algoritmo que usa @Risk internamente.

2.3 Distribución de Bernoulli B(p)

Modela la ocurrencia binaria de un riesgo: ocurre con probabilidad p, o no ocurre con probabilidad 1−p.

CondiciónResultadoInterpretación
u < pX = 1El riesgo se materializa
u ≥ pX = 0El riesgo no ocurre
EstadísticoFórmula
MediaE[X] = p
VarianzaVar[X] = p · (1 − p)

2.4 Modelo Combinado: Bernoulli × Triangular

El impacto de un riesgo en la iteración i se modela como el producto de su ocurrencia Bernoulli y su impacto triangular. Si el riesgo no ocurre, su contribución es exactamente cero:

R_k(i) = B_k(i) · T(a_k, c_k, b_k)

Valor Esperado: VE_k = p_k · E[T_k] = p_k · (a_k + c_k + b_k) / 3
Varianza: Var_k = p_k(1−p_k)·E[T_k]² + p_k·Var[T_k]

Ciclo de Simulación — Caja Blanca (Seudocódigo)

El siguiente seudocódigo describe exactamente el algoritmo ejecutado por el motor de simulación. El código es auditable: cada operación matemática corresponde a las fórmulas de la Sección 2. No existen cajas negras.

3.1 Motor Principal — RunSimulation()

FUNCION RunSimulation(items[], risks[], N = 10.000):
    resultados = new double[N]

    PARA i = 0 HASTA N-1:
        eat = certeza_base              // componente fijo comprometido

        PARA CADA ítem j en items[]:
            eat += InvCDF_Triang(Rand(), j.min, j.probable, j.max)

        PARA CADA riesgo k en risks[]:
            Si Rand() < k.probabilidad:  // Bernoulli: ¿ocurre?
                impacto = InvCDF_Triang(Rand(), k.min, k.probable, k.max)
                Si k.esAmenaza: eat += impacto  // amenaza suma
                Sino:           eat -= impacto  // oportunidad resta

        resultados[i] = eat

    ORDENAR(resultados)                 // ascendente para percentiles
    RETORNAR calcularEstadisticas(resultados)

3.2 Función InvCDF_Triangular — Muestreo Exacto

FUNCION InvCDF_Triang(u, a, c, b):
    F_c = (c − a) / (b − a)    // umbral de la moda

    Si u < F_c:
        RETORNAR  a + √[ u · (b−a) · (c−a) ]
    Sino:
        RETORNAR  b − √[ (1−u) · (b−a) · (b−c) ]

// Complejidad: O(1) — sin rechazo — u genera exactamente 1 muestra

3.3 Cálculo de Estadísticas de Salida

Percentil q (array resultados[] ordenado, N = 10.000):
  i = (q / 100) · (N − 1)
  P_q = res[⌊i⌋] + frac(i) · (res[⌊i⌋+1] − res[⌊i⌋])   ← interpolación lineal AACE

CVaR_α = promedio de todos los res[k] donde res[k] > P_α

Tornado (Swing_j) = EAT(x_j = max_j) − EAT(x_j = min_j)

EAT Combinado y Métricas de Riesgo

4.1 EAT por Iteración — Estimado al Término

EAT(i) = Certeza + Σⱼ T(aⱼ, cⱼ, bⱼ) + Σₖ Bₖ · T(aₖ, cₖ, bₖ)

E[EAT] = Certeza + Σⱼ (aⱼ+cⱼ+bⱼ)/3 + Σₖ pₖ·(aₖ+cₖ+bₖ)/3

4.2 CVaR — Conditional Value at Risk (Expected Shortfall)

El CVaR al nivel α responde: «si el proyecto cae en el peor (1−α)% de escenarios, ¿cuál es el costo promedio esperado?». Es una medida de riesgo coherente en el sentido de Artzner (1999), superior al simple percentil porque cuantifica la severidad de la cola:

CVaR_α = E[ EAT | EAT > P_α ]
       = (1 / N·(1−α)) · Σ{ EAT(i) : EAT(i) > P_α }

Exceso de cola:  Excess_P90 = CVaR_90 − P90
Alerta AACE:    Excess_P90 > 5% del CAPEX → cola gorda; mitigar top-Tornado

Correlación entre Variables — Cópula Gaussiana + Cholesky

Cuando los ítems o riesgos de un proyecto están correlacionados (por ejemplo, la inflación de materiales afecta simultáneamente a múltiples contratos), asumir independencia subestima el riesgo del portafolio. La Cópula Gaussiana con descomposición de Cholesky resuelve esto generando variables con las distribuciones marginales correctas y la estructura de dependencia especificada.

⚠️

Impacto Cuantitativo

En proyectos con correlación media ρ = 0.5 entre contratos, el P90 correlacionado puede superar al P90 independiente entre un 15% y un 25%. Este efecto «tormenta perfecta» es completamente invisible sin la Cópula Gaussiana y es crítico para el dimensionamiento correcto de contingencias.

5.1 Algoritmo Cópula Gaussiana — 3 Pasos

PASO 1: Generar vectores correlacionados en espacio normal
    W ~ N(0, I)        → n vectores normales estándar INDEPENDIENTES
    L = Cholesky(Σ)   → factorización de la matriz de correlación Σ
    Z = L · W          → Z ~ N(0, Σ) normal multivariada correlacionada

PASO 2: Transformar a uniformes correlacionadas
    U_j = Φ(Z_j)       → Φ = CDF de la normal estándar
                           U_j ~ U(0,1) con estructura de dependencia Σ

PASO 3: Transformar a la distribución marginal de cada variable
    X_j = InvCDF_j(U_j)
    X_j tiene distribución T(aⱼ, cⱼ, bⱼ) con correlación ρᵢⱼ

5.2 Factorización de Cholesky

Objetivo: descomponer Σ = L · Lᵀ, donde Σ es la matriz de correlación n×n (simétrica, definida positiva) y L es la matriz triangular inferior.

L[i,i] = √( Σ[i,i] − Σ_{k<i} L[i,k]² )
L[i,j] = (Σ[i,j] − Σ_{k<j} L[i,k]·L[j,k]) / L[j,j]    para i > j

Requisito: todos los autovalores de Σ deben ser > 0
Complejidad: O(n³) — eficiente para matrices de hasta ~100 variables

Integración en Ruta Crítica (SRA — CPM Estocástico)

El Análisis de Riesgo de Cronograma (SRA — AACE RP-57R-09) integra las variables de riesgo directamente en el modelo de red CPM. En cada iteración Monte Carlo, cada tarea recibe una duración muestreada de su distribución triangular y se recalcula el camino crítico completo. La distribución del plazo total emerge de 10.000 ejecuciones del algoritmo CPM.

6.1 CPM Estocástico por Iteración

PARA CADA iteración i = 1..N:

    // Paso 1: Muestrear duración de cada tarea
    d_j(i) = InvCDF_Triang(Rand(), min_j, probable_j, max_j)

    // Paso 2: Forward Pass — calcular inicio/fin más temprano
    ES_j(i) = max{ EF_pred(i) para todos los predecesores de j }
    EF_j(i) = ES_j(i) + d_j(i)

    // Paso 3: Duración total del proyecto
    D_total(i) = max_j{ EF_j(i) }        ← nodo final de la red

Distribución de D_total sobre N iteraciones → P50, P80, P90

6.2 Índice de Criticidad Estocástica

IC_j = (# iteraciones en que j es tarea crítica) / N     ∈ [0, 1]

IC_j = 1.0 (100%) → crítica en TODOS los escenarios
IC_j = 0.5 ( 50%) → crítica en la mitad de los escenarios
IC_j < 0.2 ( 20%) → raramente crítica; bajo riesgo de impacto
🔍

Clave para Auditores

La ruta crítica CAMBIA entre iteraciones. Una tarea no crítica en el escenario base puede volverse crítica en el escenario P90 si su duración muestreada aumenta lo suficiente. Este fenómeno —criticidad estocástica— es invisible en el CPM determinístico tradicional y es precisamente lo que el SRA cuantifica.

Validación Matemática (Caja Blanca)

Los siguientes casos de prueba tienen solución analítica cerrada. El motor Monte Carlo debe converger a estos valores dentro de las tolerancias indicadas para N = 10.000 iteraciones. Esto permite a los auditores verificar la corrección del sistema de forma completamente independiente.

7.1 Test 1 — Distribución Triangular Simple

Entrada: T(a=1, c=2, b=3)

E[T] = (1 + 2 + 3) / 3 = 2.0000
Var[T] = (1+4+9 − 2−3−6) / 18 = 3/18 = 0.1667
σ = √0.1667 = 0.4082

Criterio MC (N=10.000): |media_MC − 2.000| / 2.000 < 1.0%
Error estándar teórico: 0.4082 / √10.000 = 0.00408 (0.2%)

7.2 Test 2 — Bernoulli × Triangular

Entrada: riesgo con p=0.5, impacto T(a=0, c=1, b=2)

E[T] = (0 + 1 + 2) / 3 = 1.0
VE = p · E[T] = 0.5 · 1.0 = 0.5000
Var[T] = (0+1+4−0−0−2)/18 = 3/18 = 0.1667
Var[B·T] = 0.5·0.5·1.0 + 0.5·0.1667 = 0.3333

Criterio: |media_MC − 0.500| / 0.500 < 2.0%

7.3 Test 3 — Suma de n Triangulares (Teorema Central del Límite)

Entrada: n=5 ítems idénticos, cada uno T(a=1, c=2, b=3)

E[Σ] = 5 · 2.0 = 10.000
Var[Σ] = 5 · 0.1667 = 0.8333    σ = 0.9129

Por TCL, la suma se aproxima a N(10, 0.913)
Criterio: |media_MC − 10.000| < 0.100 (1% relativo)

7.4 Criterio General de Convergencia (Ley de Grandes Números)

Error_rel = |media_MC − media_teórica| / |media_teórica| < 1%

Para CV = 15% y N = 10.000:
  Error_estándar_rel = 0.15 / √10.000 = 0.15% ≪ 1%

N = 50.000 reduce el error a ≈ 0.067% sin cambio de método.
